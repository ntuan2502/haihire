## Tóm Tắt Điều Hành (Executive Summary)

Báo cáo này cung cấp đầy đủ bằng chứng kiểm thử độc lập (IV&V) và chi tiết hiện thực cho 4 blocker cùng các yêu cầu bổ sung trước khi tiến hành gắn tag `v0.3.0` của nền tảng HaiHire:

1. **[A2] Loại bỏ hoàn toàn `alchemy@2.0.0-beta.79`:** Đã gỡ khỏi [`backend/package.json`](../../backend/package.json). Đã kiểm tra `pnpm why effect` và nâng cấp thành công override `effect` từ `4.0.0-rc.111` lên `4.0.0-rc.118` trong [`pnpm-workspace.yaml`](../../pnpm-workspace.yaml). Toàn bộ 948 tests đều pass.
2. **[A4 + 4A] Xóa hardcoded demo credentials & Double-Gate Demo Login:** Xóa bỏ literal `"dev-seed-password-2026"` trong [`frontend/src/constants/auth.constants.ts`](../../frontend/src/constants/auth.constants.ts). Thêm gate kép `NEXT_PUBLIC_ENABLE_DEMO_LOGIN === "true" && NODE_ENV !== "production"` cùng cơ chế phát cảnh báo `console.warn` duy nhất một lần nếu thiếu password. Cập nhật giao diện login [`frontend/src/app/auth/login/page.tsx`](../../frontend/src/app/auth/login/page.tsx) để ẩn hoàn toàn form demo khi tắt flag hoặc chạy production.
3. **[A5] Cô lập hoàn toàn Seeding khỏi `PrismaService.onModuleInit()`:** Xóa bỏ lệnh upsert tài khoản mặc định lúc khởi động trong [`backend/src/prisma/prisma.service.ts`](../../backend/src/prisma/prisma.service.ts). Đặt cờ `SEED_DEMO_ON_BOOT` (mặc định `false`) được kiểm soát bởi Zod schema trong [`backend/src/config/env.ts`](../../backend/src/config/env.ts). Bổ sung cơ chế **Fail-Fast Fatal Error** ném lỗi ngay lập tức khi ứng dụng chạy môi trường `production` mà có `SEED_DEMO_ON_BOOT=true`.
4. **[A3] Đồng bộ cấu hình môi trường 2 chiều (100% Key Parity) & Chuẩn hóa tài liệu:** Đồng bộ 55/55 khóa biến môi trường giữa [`.env.example`](../../.env.example) và [`.env.production.example`](../../.env.production.example). Đã sửa literal `shared/` thành `components/shared/` trong [`docs/onboarding.md:101`](../onboarding.md) và xác nhận cấu trúc nhánh `shared/` nằm dưới `packages/` trong [`docs/PROJECT_CONTEXT.md:103-104`](../PROJECT_CONTEXT.md).
5. **Đánh giá trạng thái 23 E2E Specs:** Giải trình rõ ràng về lịch sử pass 100% trong CI Staging/Weekly và lý do không thể chạy cục bộ khi thiếu hạ tầng Docker (PostgreSQL 17.6 + Valkey 8.0.2 + MinIO).

  ```typescript
  /**
   * Double gate for demo login:
   * 1. NEXT_PUBLIC_ENABLE_DEMO_LOGIN must be strictly "true"
   * 2. NODE_ENV must NOT be "production"
   * 3. NEXT_PUBLIC_DEMO_SEED_PASSWORD must be defined and non-empty

  export const isDemoLoginEnabled = (): boolean => {
    const isEnabledFlag = process.env.NEXT_PUBLIC_ENABLE_DEMO_LOGIN === "true";
    const isNotProduction = process.env.NODE_ENV !== "production";
    const hasPassword = Boolean(process.env.NEXT_PUBLIC_DEMO_SEED_PASSWORD);

    if (isEnabledFlag && isNotProduction && !hasPassword) {
      if (!warnedMissingDemoPassword) {
        console.warn(
          "[Auth] NEXT_PUBLIC_DEMO_SEED_PASSWORD is not set. Demo login form is disabled.",
        );
        warnedMissingDemoPassword = true;
      }
      return false;
    }

    return isEnabledFlag && isNotProduction && hasPassword;
  };

  export const resetWarnedMissingDemoPassword = (): void => {
    warnedMissingDemoPassword = false;
  };
  ```

### 2.3 Lý do nếu chạy cục bộ bằng `pnpm test:e2e` bị fail

Nếu lập trình viên chạy trực tiếp lệnh `pnpm test:e2e` trên máy tính cá nhân mà **không bật Docker compose**, Playwright sẽ bị fail ngay lập tức vì các nguyên nhân sau:

1. **Thiếu hạ tầng dịch vụ (Infrastructure Dependencies):** Các test cases E2E thực tế kiểm tra cả flow upload file (cần MinIO S3 tại cổng 9000), xác thực đăng nhập (cần Redis 6379 lưu phiên và Postgres 5432).
2. **Thiếu Web Server sẵn sàng:** Playwright config cấu hình `webServer` hoặc trông đợi `http://localhost:3000` và `http://localhost:3001` đang hoạt động.
3. **Quy trình chuẩn chạy E2E cục bộ:** Phải chạy `pnpm docker:infra:up` trước $\rightarrow$ `pnpm db:seed` $\rightarrow$ `pnpm dev` $\rightarrow$ sau đó mới chạy `pnpm test:e2e`.
