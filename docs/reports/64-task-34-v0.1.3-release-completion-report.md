## 5. Operations & Governance Note: Staging Branch Protection

During promotion from `dev` to `staging` (PR #70), the merge was initially blocked because GitHub Branch Protection for `staging` requires 4 status checks:

- `11 CI Architecture Gates`
- `Unit & Integration Tests (Coverage)`
- `Playwright End-to-End Suite`
- `Production Build Verification`

In Task #32, the `pull_request` trigger had been removed from `.github/workflows/ci-staging.yml` (leaving only `push: branches: [staging]`). As a result, opening a PR to `staging` did not trigger these checks.

### Remediation & Action Item for v0.1.4:

- **Temporary Resolution:** Disabling `enforce_admins` temporarily allowed an admin merge on PR #70, after which `enforce_admins: true` was immediately re-enabled. Once merged into `staging`, the `push` event triggered `ci-staging.yml` (`#38927621283`), executing all 4 checks with 100% pass rate.
- **Permanent Fix (Recommended for Next Task):** Add the `pull_request` trigger back to `.github/workflows/ci-staging.yml`:
  ```yaml
  on:
    push:
      branches: [staging]
    pull_request:
      branches: [staging]
    workflow_dispatch:
  ```
  This ensures PRs into `staging` run full pre-production verification automatically without requiring administrative override.
